## 🔹 ЧАСТЬ 1: 🌐 IP-АДРЕС

### ❓ Что это?

**IP-адрес** (Internet Protocol address) — уникальный сетевой адрес устройства в сети, работающей по протоколу IP. Позволяет идентифицировать устройство и маршрутизировать данные между сетями.

### ⚙️ Как использовать?

| Задача | Способ |
|--------|--------|
| Узнать свой локальный IP | `ipconfig` (Windows) / `ifconfig` или `ip a` (Linux/macOS) |
| Узнать внешний (публичный) IP | Сайты: `2ip.ru`, `whatismyip.com`, `ipinfo.io` |
| Задать статический IP | Настройки сетевого адаптера / веб-интерфейс роутера |
| Протестировать связь с устройством | Команда `ping <IP-адрес>` (например, `ping 8.8.8.8`) |
| Проверить маршрут до сервера | Команда `tracert <домен>` (Windows) / `traceroute <домен>` (Linux) |

### ⚡ Особенности

#### Версии протокола

- **IPv4**
  - Длина: 32 бита
  - Формат: `192.168.0.1` (4 числа от 0 до 255)
  - Количество адресов: ~4,3 миллиарда
  - Статус: исчерпан, но всё ещё широко используется

- **IPv6**
  - Длина: 128 бит
  - Формат: `2001:0db8:85a3::8a2e:0370:7334` (шестнадцатеричный)
  - Количество адресов: ~340 секстиллионов
  - Статус: будущее интернета, постепенное внедрение

#### Типы назначения

| Тип | Диапазоны (IPv4) | Назначение |
|-----|-----------------|------------|
| 🟢 Публичный | Любой, кроме частных | Виден в интернете, уникален глобально |
| 🔵 Частный | `10.0.0.0–10.255.255.255`<br>`172.16.0.0–172.31.255.255`<br>`192.168.0.0–192.168.255.255` | Используется внутри локальных сетей |

#### Способ получения

- 🔄 **Динамический** — выдаётся автоматически по DHCP, может меняться при переподключении
- 🔒 **Статический** — задаётся вручную, не меняется, используется для серверов и сетевого оборудования

#### Дополнительно

- По публичному IP можно определить примерное географическое положение (страна, город, провайдер)
- Провайдеры, сайты и государственные органы могут вести логирование активности по IP
- NAT (Network Address Translation) позволяет нескольким устройствам выходить в интернет под одним публичным IP

### 💡 Пример

```text
Сценарий: Вы открываете сайт example.com

Устройства и адреса:
┌─────────────────────────────────┐
│ Ваше устройство                 │
│ • Локальный IP: 192.168.1.15    │
│ • MAC: A4:5E:60:C2:1F:3B        │
└─────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────┐
│ Ваш роутер                      │
│ • Локальный IP: 192.168.1.1     │
│ • Публичный IP: 89.123.45.67    │
│ • MAC: B8:27:EB:4A:2C:1D        │
└─────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────┐
│ Сервер сайта example.com        │
│ • IP: 142.250.185.46            │
│ • MAC: (не виден вам напрямую)  │
└─────────────────────────────────┘

Путь запроса:
[Ваш ПК] 
   → (по локальной сети, по MAC) 
[Роутер] 
   → (по интернету, по публичному IP) 
[Сервер]
```

> 📌 **Важно:** В интернете сайты видят публичный IP вашего роутера, а не локальный адрес вашего устройства. Это обеспечивает базовый уровень приватности, но не полную анонимность.

## 🔹 ЧАСТЬ 2: 🔧 MAC-АДРЕС

### ❓ Что это?

**MAC-адрес** (Media Access Control) — уникальный физический идентификатор сетевого интерфейса (сетевой карты, Wi‑Fi‑модуля, Bluetooth‑адаптера), «прошитый» производителем на этапе изготовления оборудования.

### ⚙️ Как использовать?

| Задача | Способ |
|--------|--------|
| Узнать MAC-адрес в Windows | `getmac` / `ipconfig /all` в командной строке |
| Узнать MAC-адрес в Linux | `ip link show` / `ifconfig` в терминале |
| Узнать MAC-адрес в macOS | `ifconfig` / «Системные настройки → Сеть → Дополнительно → Оборудование» |
| Настроить фильтрацию по MAC | Веб-интерфейс роутера → «Контроль доступа» / «Фильтр MAC-адресов» |
| Посмотреть ARP-таблицу (соответствие IP→MAC в локальной сети) | Команда `arp -a` |
| Временно изменить MAC (для тестов) | `macchanger` (Linux) / настройки адаптера (Windows) / сторонние утилиты |

### ⚡ Особенности

#### Формат и структура

```text
Пример MAC-адреса:  A4:5E:60:C2:1F:3B
                    │    │    │    │    │    │
                    └────┴────┴────┴────┴────┘
                    6 байт = 48 бит = 12 шестнадцатеричных символов

Структура:
┌─────────────────┬─────────────────┐
│  A4:5E:60       │  C2:1F:3B       │
│  (OUI)          │  (NIC Specific) │
└─────────────────┴─────────────────┘
       ↓                   ↓
Код производителя    Уникальный номер
(выдаётся IEEE)      устройства внутри партии
```

#### Технические характеристики

| Параметр | Значение |
|----------|----------|
| Длина | 48 бит (6 байт) |
| Представление | Шестнадцатеричное, разделители `:`, `-` или без них |
| Уникальность | Гарантируется комбинацией OUI + серийный номер |
| Уровень OSI | Канальный (Уровень 2) |
| Область действия | Только в пределах одного сегмента локальной сети |
| Маршрутизация | Не маршрутизируется за пределы LAN |

#### Важные нюансы

- 🔹 **Не выходит в интернет:** Маршрутизаторы удаляют MAC-адреса из кадров при передаче между сетями. В глобальной сети используется только IP.
- 🔹 **Возможна подмена (MAC spoofing):** Программное изменение адреса для обхода фильтров, тестирования или анонимизации в локальной сети.
- 🔹 **Универсальный/Локальный бит:** Второй младший бит первого байта указывает, является ли адрес универсальным (0) или локально назначенным (1).
- 🔹 **Индивидуальный/Групповой бит:** Младший бит первого байта указывает, является ли адрес индивидуальным (0) или групповым/вещательным (1).

### 💡 Пример

```text
Сценарий: Передача файла с ноутбука на принтер в одной Wi‑Fi сети

Устройства:
┌────────────────────────────────────┐
│ Ноутбук                            │
│ • IP: 192.168.1.15                 │
│ • MAC: A4:5E:60:C2:1F:3B           │
└────────────────────────────────────┘

┌────────────────────────────────────┐
│ Сетевой принтер                    │
│ • IP: 192.168.1.50                 │
│ • MAC: D8:9E:F3:1A:2B:4C           │
└────────────────────────────────────┘

Процесс передачи:
1. Ноутбук проверяет: 192.168.1.50 находится в той же подсети
2. Отправляет ARP-запрос: «Кто имеет IP 192.168.1.50?»
3. Принтер отвечает: «Это я, мой MAC — D8:9E:F3:1A:2B:4C»
4. Ноутбук формирует кадр уровня 2:
   • Источник (MAC): A4:5E:60:C2:1F:3B
   • Назначение (MAC): D8:9E:F3:1A:2B:4C
   • Данные: пакет с заданием на печать
5. Принтер получает кадр, проверяет свой MAC, извлекает пакет и печатает документ
```

> 📌 **Важно:** Если бы принтер находился в другой сети, ноутбук отправил бы кадр не на MAC принтера, а на MAC шлюза (роутера), а дальнейшую доставку обеспечила бы маршрутизация по IP.

## 🔹 ЧАСТЬ 3: 📚 DNS

### ❓ Что это?

**DNS** (Domain Name System) — распределённая иерархическая система преобразования удобных для человека доменных имён (`yandex.ru`, `google.com`) в числовые IP-адреса (`77.88.55.77`, `142.250.185.46`), необходимые для маршрутизации в интернете.

### ⚙️ Как использовать?

| Задача | Способ |
|--------|--------|
| Узнать IP домена | `nslookup <домен>` / `dig <домен>` / `ping <домен>` |
| Проверить, какой DNS-сервер используется | `ipconfig /all` (Windows) / `cat /etc/resolv.conf` (Linux) |
| Сменить DNS-сервер вручную | Настройки сетевого подключения / настройки роутера |
| Ускорить разрешение имён | Использовать быстрые публичные DNS: `1.1.1.1`, `8.8.8.8`, `77.88.8.8` |
| Проверить кэш DNS | `ipconfig /displaydns` (Windows) / `systemd-resolve --statistics` (Linux) |
| Протестировать работу разных записей | `dig <домен> MX` (почта), `dig <домен> TXT` (SPF/DKIM) |

### ⚡ Особенности

#### Иерархическая структура

```text
Корневые серверы (.)
        │
        ▼
Домены верхнего уровня (TLD)
├── Общие: .com, .org, .net, .info
├── Национальные: .ru, .de, .cn, .uk
├── Новые: .app, .dev, .blog, .xyz
        │
        ▼
Домены второго уровня
├── example.com
├── yandex.ru
├── github.io
        │
        ▼
Поддомены (третьего уровня и ниже)
├── mail.yandex.ru
├── docs.github.io
├── api.service.example.com
```

#### Кэширование

Результаты DNS-запросов сохраняются на нескольких уровнях для ускорения повторных обращений:

```text
Уровни кэширования (от ближнего к дальнему):
1. Кэш браузера (несколько минут)
2. Кэш операционной системы (минуты–часы)
3. Кэш роутера / локального DNS-резолвера
4. Кэш DNS-сервера провайдера
5. Кэш авторитетных серверов домена

TTL (Time To Live) — параметр записи, указывающий, 
сколько секунд кэш считается действительным.
```

#### Основные типы записей

| Тип записи | Назначение | Пример значения |
|------------|------------|-----------------|
| `A` | Сопоставление домена с IPv4 | `example.com → 93.184.216.34` |
| `AAAA` | Сопоставление домена с IPv6 | `example.com → 2606:2800:220::1` |
| `CNAME` | Псевдоним (алиас) домена | `www.example.com → example.com` |
| `MX` | Почтовый сервер для домена | `example.com → mail.example.com (приоритет 10)` |
| `TXT` | Произвольный текст (верификация, SPF, DKIM) | `v=spf1 include:_spf.google.com ~all` |
| `NS` | Указание авторитетных DNS-серверов домена | `example.com → ns1.provider.com` |
| `PTR` | Обратное преобразование: IP → домен | `34.216.184.93.in-addr.arpa → example.com` |
| `SRV` | Описание расположения сервисов (порт, протокол) | `_sip._tcp.example.com` |

#### Безопасность

| Механизм | Описание | Зачем нужен |
|----------|----------|-------------|
| **DNSSEC** | Цифровая подпись зон и записей | Защита от подмены ответов (spoofing) |
| **DoH** (DNS over HTTPS) | Шифрование запросов через HTTPS | Конфиденциальность, обход цензуры |
| **DoT** (DNS over TLS) | Шифрование запросов через TLS | Конфиденциальность на транспортном уровне |
| **Ответы с ограничением** | Ограничение выдачи данных по зоне | Снижение рисков утечки информации |

> ⚠️ **Угрозы:**
> - **DNS spoofing / cache poisoning** — злоумышленник подменяет ответы сервера, перенаправляя пользователя на фишинговый сайт
> - **DNS tunneling** — использование DNS-трафика для обхода файрволов и передачи данных
> - **DDoS на DNS-инфраструктуру** — вывод из строя серверов, что делает домены недоступными

### 💡 Пример

```text
Сценарий: Вы вводите в браузере "https://yandex.ru"

Шаг 1: Проверка локального кэша
├─ Браузер: есть ли запись в своём кэше? → Нет
├─ ОС: есть ли запись в системном кэше? → Нет

Шаг 2: Запрос к настроенному резолверу
├─ ОС отправляет запрос на DNS-сервер (например, 8.8.8.8)
├─ Запрос: «Какой A-запись у yandex.ru?»

Шаг 3: Рекурсивный поиск (если нужно)
├─ 8.8.8.8 проверяет свой кэш → нет записи
├─ Запрашивает у корневого сервера: «Где зона .ru?»
├─ Корневой сервер отвечает: «Обратитесь к серверам .ru»
├─ 8.8.8.8 запрашивает у серверов .ru: «Где зона yandex.ru?»
├─ Серверы .ru отвечают: «Авторитетные серверы yandex.ru: ns1.yandex.ru, ns2.yandex.ru»
├─ 8.8.8.8 запрашивает у ns1.yandex.ru: «A-запись для yandex.ru?»
├─ ns1.yandex.ru отвечает: «yandex.ru → 77.88.55.77, TTL=300»

Шаг 4: Возврат ответа
├─ 8.8.8.8 сохраняет запись в кэш на 300 секунд
├─ Отправляет ответ вашей ОС: «77.88.55.77»

Шаг 5: Установление соединения
├─ Браузер получает IP 77.88.55.77
├─ Инициирует TCP-соединение + TLS-рукопожатие
├─ Отправляет HTTP-запрос: «GET / HTTP/1.1, Host: yandex.ru»
├─ Сервер возвращает HTML-страницу → вы видите сайт

Визуально:
[Вы: yandex.ru] 
   → [DNS: 77.88.55.77] 
   → [Браузер: подключается к 77.88.55.77:443] 
   → [Сервер: отправляет контент] 
   → [Вы: видите страницу]
```

> 📌 **Важно:** Без DNS вам пришлось бы запоминать и вводить числовые IP-адреса всех сайтов вручную. Также именно на этапе DNS могут применяться фильтрация контента, родительский контроль и блокировки.

## 🔹 ОБЩИЙ ВЫВОД 🎯

### 🔄 Как IP, MAC и DNS работают вместе?

```text
┌─────────────────────────────────────────────┐
│ 1. Пользователь вводит: "google.com"        │
└─────────────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────────┐
│ 2. DNS-запрос:                               │
│    • Проверяется локальный кэш               │
│    • При необходимости — рекурсивный поиск   │
│    • Результат: 142.250.185.46               │
└─────────────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────────┐
│ 3. Определение маршрута:                     │
│    • ОС понимает, что адрес не локальный     │
│    • Нужно отправить пакет на шлюз (роутер)  │
└─────────────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────────┐
│ 4. ARP-запрос в локальной сети:              │
│    • «Какой MAC у роутера (192.168.1.1)?»    │
│    • Роутер отвечает своим MAC               │
└─────────────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────────┐
│ 5. Инкапсуляция и отправка:                  │
│    • Внутри пакета: IP отправителя → IP цели │
│    • В кадре Ethernet: MAC отправителя → MAC │
│      роутера                                 │
└─────────────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────────┐
│ 6. Маршрутизация в интернете:                │
│    • Роутеры смотрят только на IP-заголовки  │
│    • MAC-адреса меняются на каждом hop       │
└─────────────────────────────────────────────┘
```

### 📋 Сводная таблица

| Критерий | **IP-адрес** | **MAC-адрес** | **DNS** |
|----------|-------------|---------------|---------|
| **Суть** | Логический сетевой адрес | Физический адрес интерфейса | Система преобразования имён |
| **Уровень OSI** | Сетевой (3) | Канальный (2) | Прикладной (7) |
| **Где работает** | Глобально (интернет) | Локально (один сегмент сети) | Глобально (справочная инфраструктура) |
| **Формат** | `192.168.1.1` (IPv4) / `2001::1` (IPv6) | `A4:5E:60:C2:1F:3B` | `example.com` → `93.184.216.34` |
| **Изменяемость** | Да (динамический/статический) | Нет (по умолчанию, но можно подменить) | Настраивается администратором |
| **Главная задача** | Маршрутизация между сетями | Доставка кадров внутри сегмента | Удобство для человека (имена вместо цифр) |

### ✅ Ключевая мысль (аналогия)

> 🌐 **IP-адрес** — это *«почтовый индекс»* города и улицы: нужен, чтобы письмо дошло до нужного населённого пункта.  
> 🔧 **MAC-адрес** — это *«номер квартиры»* в доме: нужен, чтобы письмо попало именно к вам внутри здания.  
> 📚 **DNS** — это *«телефонный справочник»*: чтобы не запоминать индексы, вы ищете по имени «Иван Иванов», а система подсказывает адрес.

🔹 **Без любого из трёх компонентов современный интернет работать не сможет.**

## 📎 Приложения

### 🔧 Полезные команды для практики

```bash
# Windows
ipconfig /all          # вся информация о сети
getmac                 # только MAC-адреса
nslookup yandex.ru     # запрос к DNS
arp -a                 # таблица соответствия IP→MAC в локальной сети
tracert google.com     # трассировка маршрута

# Linux / macOS
ip a                   # IP-адреса интерфейсов
ip link                # MAC-адреса
dig yandex.ru          # подробный DNS-запрос
arp -n                 # ARP-таблица
traceroute google.com  # трассировка маршрута
```

### 🌐 Публичные DNS-серверы

| Провайдер | IPv4 | IPv6 | Особенности |
|-----------|------|------|-------------|
| **Cloudflare** | `1.1.1.1`, `1.0.0.1` | `2606:4700:4700::1111` | Быстрый, приватный, без логов |
| **Google** | `8.8.8.8`, `8.8.4.4` | `2001:4860:4860::8888` | Надёжный, глобальный |
